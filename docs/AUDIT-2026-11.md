# Audit — November 2026

First maintenance pass since April 2026 (last commit `814bb49`, 2026-04-27).
Scope: test coverage, small correctness fixes, dependency/state-of-the-art
review against primary sources (checked 2026-11-02/03). Companion to
`DESIGN.md`, which still describes the architecture accurately — the shape
(OAuth + PoToken + remote cipher in depth, loopback-only helpers,
endpoint-level docker-socket-proxy allowlist) remains the recommended one.
The drift was in versions, config, and test infrastructure, not architecture.

## Tests: 30 → 161, coverage 49% → 92%

Headline finding: **the suite did not run in a clean environment.**
`app.main` builds `Settings()` at import time; with `ADMIN_PASSWORD`,
`ADMIN_SECRET_KEY`, `LAVALINK_PASSWORD` unset, collection died with a
pydantic `ValidationError`. There was no CI, so nothing noticed.

- `admin/tests/conftest.py` now supplies test env *before* any `app` import
  (`setdefault` — real env still wins), resets the global config lock per
  test (pytest-asyncio gives each test a fresh loop), and provides
  lifespan-free `client`/`authed_client` fixtures (not entering the
  TestClient context = no APScheduler, no Docker log tail).
- New coverage: `StateStore`, `docker_ctl`, OAuth rotation, the `/healthz`
  contract (Lavalink critical, cipher/pot advisory), HTTP-level
  login/middleware flow, config-router conditional writes, track-tester
  branches, log filters, tokens masking/status, cipher/pot/lavalink
  services, settings, and a contract test pinning the shipped
  `application.yml` paths that `setup.sh`'s indentation-keyed `sed` and the
  PoT/OAuth writers depend on.
- `.github/workflows/ci.yml` (new — the repo had no CI): pytest + coverage,
  pyflakes, `docker compose config -q`, `terraform fmt -check`. The compose
  and terraform checks were verified locally with the real binaries.

## Bugs the new tests caught (fixed)

1. `StateStore._ensure_dir` crashed on a bare-filename state path
   (`os.makedirs("")` raises). Guarded; `write()` falls back to `"."`.
2. `docker_ctl.stream_logs` had a dead `except docker.errors.NotFound`
   branch — `get_container()` already translates that to `ValueError`, so a
   missing container reported "Stream interrupted" instead of "not found".
   Now catches `ValueError`.
3. `write_config_to_disk` left a partial `.tmp` file behind when the YAML
   dump itself failed. Now cleaned up on dump errors.
4. `log_watcher`: extracted `process_log_line(line, state)` from the
   infinite loop so the OAuth device-code/success parsing — the sole source
   of the code shown on the Tokens page — is unit-testable. Removed the
   unused `get_container` import; pyflakes is now clean across `app/` and
   `tests/`.

## State of the art — findings, no action taken (owner decisions)

- **DAVE (Lavalink 4.2.x):** Discord E2EE voice support; voice state gained
  a *required* `channelId`. The ops side is fine, but the **client library
  (CrackTunes) must support DAVE and supply `channelId`**, or voice connect
  fails. Verify before deploying the pinned 4.2.2 anywhere live.
- **PoToken scope is much narrower than the rotation assumes.**
  youtube-source README: a poToken "only applies to requests made via the
  `WEB` & `WEBEMBEDDED` client" and "You do not need to use `poToken` with
  OAuth." The current client list is `MUSIC, TV, WEB, WEBEMBEDDED, IOS,
  ANDROID_VR` and OAuth is enabled (TV path) — so the 6-hourly
  rotate-and-restart-Lavalink cycle buys protection for only part of the
  traffic and costs a player-dropping restart each time. Worth an explicit
  decision: drop the scheduled rotation, lengthen it, or keep as-is with
  eyes open.
- **`TVHTML5_SIMPLY`** is a current youtube-source client (Opus, playback +
  livestream, Video/Search/Mix metadata) not in our list; `TVHTML5EMBEDDED`
  was removed upstream. Trial `TVHTML5_SIMPLY` (e.g. after `WEBEMBEDDED`)
  via the track tester before changing the shipped order.
- **bgutil:** our pin (`jim60105/bgutil-pot:v0.8.1`, the Rust fork) is still
  that fork's latest release — not stale. The upstream JS provider
  (Brainicism) is at 2.0.2; its 2.0.0 was a security release
  (GHSA-qpv9-8xfj-xx9m, RCE via the old `0.0.0.0` default bind). **Do not**
  swap to the JS image below 2.0.2; if swapping, keep the loopback publish
  and re-test the `/get_pot` contract.
- **docker-socket-proxy:** `0.3.0` is stale; v0.5.0 exists (2026-07-27).
  *Not* bumped here: our custom `haproxy.cfg` rides on the image's
  template/sed entrypoint behaviour, which changed across 0.3 → 0.4+. The
  bump needs a live stack and negative tests (create/exec/start must 403;
  restart/logs/ping/version must pass). Alternative worth evaluating at the
  same time: `wollomatic/socket-proxy` (per-method regex allowlists without
  the HAProxy template hack).
- **yt-cipher** has no releases/tags at all — `:master` is upstream's
  intended update path but unreproducible. A digest pin + track-tester gate
  is the reproducible compromise; not changed here.
- **OAuth device flow:** youtube-source now also exposes plugin REST routes
  for OAuth (`/youtube/oauth/{refreshToken}` etc.). The log-scraping flow
  still works; the REST route is a cleaner seam if the watcher gets flaky.

## Still hard to test (by design, documented)

- `start_log_watcher`'s reconnect loop (one iteration is tested with a fake
  Docker stream; the loop itself is infinite and Docker-bound).
- End-to-end YouTube playback: exogenous (BotGuard/cipher churn). The track
  tester remains the manual gate; any future integration layer should be
  opt-in (`pytest -m integration`), never in the default CI gate.
